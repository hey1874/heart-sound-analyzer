# 硬件接入与避坑

本项目针对**听诊器 → 驻极体咪头 → 声卡 → 电脑**的采集链路设计。
信号质量上限主要由硬件决定,以下是实测要点。

## 听诊器作为声学耦合器

听诊头贴胸壁,把心音经膜片/管路耦合到咪头,等效一个**低频声学放大器**。
- 听诊位置(信号最强):**胸骨左缘第 4 肋间(三尖瓣区)** 或 **心尖**。
- **贴稳、别蹭**:摩擦噪声是这类采集最大的干扰源。算法靠带通+香农能量+SQI
  压制,但物理上贴稳更重要。

## 咪头:松下 WM-61A

经典低噪声驻极体咪头,频响平直、底噪低,适合心音这种低频低声压信号。

- **偏置/供电**:驻极体需要偏置电压。接电脑 3.5mm mic-in 时通常由
  **plug-in power** 供电;若自己搭电路,用电阻从 2–10V 偏置。偏置不对会
  失真、抬底噪。
- **低频是命门**:心音基频 **20–150 Hz**。WM-61A 本身能下到很低,
  **瓶颈往往在声卡/输入口的高通**。

## 声卡 / 输入口:低频高通是最大风险点

很多 USB 声卡、手机/PC 的 mic-in 为滤工频和 handling noise,会在
**50–100 Hz 以下做高通**,这会直接砍掉 S1/S2 的能量。

- ✅ **MacBook 3.5mm 耳麦口**(本项目使用):实测低频响应较平,基本不裁掉
  心音低频,是省事可用的方案。
- ⚠️ 廉价 USB 声卡:不少在低频明显衰减,务必先测。
- 建议:用已知低频内容(或扫频)测一下输入口的低频响应;必要时选 DC 耦合
  或低频平直的音频接口。

> 代码里带通下限设 **20 Hz** 就是为了不浪费咪头/听诊器的低频——前提是声卡
> 能把这段送进来。

## 采样设置

- 采样率:**≥4000 Hz** 即可(算法内部重采样到 2000 Hz);用声卡默认
  44100/48000 Hz 也行。
- 声道:单声道即可;立体声时代码取第 0 声道。
- 增益:避免削波(SQI 的 `clip` 会监测)。留足动态范围,峰值别贴满量程。

## 可选:小米手环作参考心率

可用手环 HR 作**交叉校验**(不是真值)。注意:
- 多数型号**不在蓝牙广播里发实时心率**,需 BLE 连接 + 厂商认证握手
  (类似 Gadgetbridge 的 auth key 流程),标准心率服务 0x180D 常被锁。
- 手环 HR 是 PPG 估计、有数秒延迟,精度不一定高于听诊器声学。
- 用法:两者差异过大→提示"信号可能不可靠",而非取代声学估计。

(融合入口已在算法的 `confidence` 上预留;BLE 读取未实现,属可选扩展。)
